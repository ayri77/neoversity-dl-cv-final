# Рішення: фото важать більше за текст — CLIP/SigLIP2 zero-shot + стекінг (public 0.8088)

Ділюся рішенням і всім кодом. Основна ідея: у цьому змаганні немає табличних ознак,
а в оригінальному PetFinder 2019 найсильнішими були саме вони (вік, порода, тип тварини).
Тому я **відновлював їх з фото й тексту**, а потім склав модальності стекінгом.

**Код:** https://github.com/ayri77/neoversity-dl-cv-final — `notebooks/final_submission.ipynb` (увесь конвеєр від сирих даних до сабмішну), дослідницькі ноутбуки `01`–`07` і модулі в `src/`.

| | OOF QWK (5 фолдів) | Public LB |
|---|---|---|
| Бейзлайн (ознаки + Ridge-стекінг) | 0.6125 | 0.7912 |
| **Фінал** | **0.6210** | **0.8088** |

## 1. Дані: що варто знати

- **Класи 1–4, класу 0 немає:** 18.6 / 27.6 / 20.6 / 33.2 %. Метрика QWK порядкова, тому я
  робив **регресію + підбір порогів** (`OptimizedRounder`), а не класифікацію. Пороги дають
  0.61 проти 0.53 при простому округленні.
- **`PetID` читайте як рядок.** Є ID на кшталт `10e723583`, і pandas може прочитати їх як число.
  У 4 ID у `test.csv` втрачено ведучий нуль (`95314294` → фото `095314294-1.jpg`). Для пошуку
  фото їх треба доповнити до 9 символів, **а в сабмішні повернути як у test.csv**, інакше
  Kaggle відхилить файл («Unable to find required key value»).
- Фото лежать у `images/train/` і `images/test/`. У `test/` є 8 зайвих тварин, яких немає в CSV.
- `sample_submission.csv` містить лише 4 рядки. Сабмішн будуйте за ID з `test.csv`.

## 2. Головна знахідка: майже-дублікати оголошень

Близько 12.6 % оголошень у train — **майже однакові описи** (один волонтер, один шаблон),
і таргет усередині таких груп майже збігається: std 0.27 проти 1.12 загалом.
Те саме з фото. 208 тварин у test мають «двійника» в train.

Як я це використав:
- **kNN-target ознаки:** середній таргет найближчих сусідів (TF-IDF для тексту, CLIP для фото),
  зважений `sim⁴`, рахувався **строго out-of-fold**: для рядка з фолду *f* сусіди беруться лише з
  інших фолдів.
- **Фолди — звичайні `StratifiedKFold`, а не групові.** Train і test поділено випадково, тому
  частка «двійників» у валідаційних фолдах і в test однакова (я перевірив). Групові фолди
  занижували б оцінку й ховали б реальний сигнал.
- **Перевірка на витік:** я перераховував kNN- і Ridge-ознаки для кожного фолду без міток цього
  фолду (nested). Оцінка не впала (0.566 проти 0.558 для фото, 0.612 проти 0.611 для стекінгу).

## 3. Ознаки з тексту (ноутбук 02)

- **Регулярні вирази:** тип тварини, «малюк» (kitten/puppy), вік у місяцях (враховано англійські й
  малайські одиниці: *bulan*, *tahun*), порода чи метис, вакцинація, стерилізація, внесок,
  кількість тварин, мова.
- **Вік знаходиться у 28 % описів,** але він дуже інформативний: до 2 міс. середній клас 2.38,
  6–12 міс. — 3.11.
- **Результат:** LightGBM тільки на ознаках з тексту дає 0.246, з kNN-target — 0.319.

## 4. Ознаки з фото (ноутбук 03): найсильніша частина

Один прохід по ~38k фото **CLIP ViT-L/14** (`datacomp_xl_s13b_b90k`, open_clip) і
**SigLIP2 ViT-SO400M-16-384**. Ембедінги кешуються; SigLIP2 на RTX 4080 Laptop обробляє всі фото за ~13 хв.

- **Zero-shot ознаки** з наборів промптів, softmax усередині групи: вік (baby / young / adult / old),
  порода чи метис, шерсть, колір, кількість тварин, людина в кадрі, клітка / дім / вулиця, якість фото.
  Агрегація по тварині: перше фото, середнє й максимум.
  - Вік за фото: |ρ| = 0.31–0.35 з таргетом. Це найкраще окреме відновлення табличної ознаки.
  - Порода: |ρ| ≈ 0.28 (CLIP). У SigLIP2 ті самі промпти майже не працюють.
  - Тип тварини CLIP визначає і для ~1 900 описів, де немає ні «cat», ні «dog».
- **Технічні параметри фото:** розмір файлу й висота несподівано корелюють з таргетом
  (|ρ| ≈ 0.22–0.25). Ймовірно, це слід джерела або періоду завантаження оголошення.
- **Результат:** LightGBM тільки на ознаках з фото дає **0.558**, удвічі більше, ніж текст.

## 5. Моделі першого рівня

Кожна модель дає OOF-передбачення, які далі йдуть у стекінг.

| Модель | OOF QWK |
|---|---|
| Ridge на ембедінгах CLIP (середнє + перше фото) | 0.587 |
| Ridge на ембедінгах SigLIP2 | 0.600 |
| **Attention-голова на ембедінгах усіх фото** | **0.611** |
| Ridge на TF-IDF (слова 1–2 + символи 2–5) | 0.335 |
| DeBERTa-v3-base, fine-tuning | 0.345 |
| Ridge на текстових ембедінгах CLIP / SigLIP2 | 0.28 / 0.29 |

**Attention-голова (ноутбук 06).** Тварина — це «мішок» фото. Кожне фото подається як
ембедінг CLIP ⊕ SigLIP2 (1 920 вимірів) плюс позиційний ембедінг, далі йде gated attention
pooling (Ilse et al., 2018) і регресія. Використовую до 12 фото на тварину; під час навчання
випадково ховаю 20 % фото. Навчання йде фіксовані 7 епох, без early stopping. Ця модель
перенавчається дуже швидко: за 20 епох уже 0.584.

**DeBERTa-v3-base (ноутбук 05).** Mean pooling, dropout вимкнено, bf16, `max_len` 256,
3 епохи, ~18 хв на 5 фолдів. Результат лише трохи кращий за TF-IDF. **Стеля тексту в цій задачі —
приблизно 0.35.** Пастка: transformers 5 завантажує DeBERTa-v3 у fp16, і AdamW на таких вагах
дає NaN. Ваги треба вантажити у fp32.

## 6. Стекінг і фінал (ноутбук 07)

- **Модель 2-го рівня:** LightGBM на ручних ознаках (тексту, CLIP, SigLIP2) + OOF-передбаченнях
  7 моделей першого рівня, усього 253 ознаки. Модель регресійна, 5 сідів.
- **Варіанти 2-го рівня майже рівні:** лінійний бленд 0.620, LightGBM тільки на OOF 0.618,
  LightGBM на ознаках + OOF 0.621. Різниця в межах шуму між сідами (0.616–0.623).
- **Пороги:** `OptimizedRounder` на OOF. Чесна оцінка, де пороги підбираються на 4 фолдах
  і застосовуються до 5-го, — **0.6124**.
- **Фінальна модель** перенавчена на всьому train. Кількість раундів — середня з CV × 1.15.

**Хід експериментів:**

| Крок | OOF QWK |
|---|---|
| Текст: regex + мета-ознаки | 0.246 |
| + kNN-target по тексту | 0.319 |
| Фото: CLIP zero-shot + якість + kNN | 0.558 |
| Текст + фото, ручні ознаки | 0.576 |
| + Ridge-стекінг на ембедінгах (бейзлайн, LB 0.7912) | 0.6125 |
| + SigLIP2 | 0.617 |
| + attention-голова, 5 сідів (фінал, LB 0.8088) | 0.621 |

## 7. Що не спрацювало

- SVD / PCA ембедінгів як ознаки: +0.002. Ridge на повних ембедінгах значно кращий.
- Fine-tuning DeBERTa: приблизно на рівні TF-IDF, у стекінгу +0.005, що в межах шуму.
- Заморожені ембедінги bge-m3: 0.29.
- Схожість опису й фото в просторі CLIP: ρ ≈ 0.05.
- Текстовий токен в attention-голові.
- Складніші моделі 2-го рівня замість простого стекінгу.

## 8. Що можна спробувати далі

- Донавчити сам енкодер фото, а не тільки голову над замороженими ембедінгами.
- Окремо підібрати промпти zero-shot для SigLIP2.
- Pseudo-labeling test (з перевіркою на CV).
- Інші енкодери фото: EVA-CLIP, DINOv2.
